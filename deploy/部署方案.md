# 剪刀石头布 · 部署方案

目标实例：`https://c404ctf.jellyspot.cc`（比赛 3 / 题目 326）

## 1. 题目形态

| 项目 | 取值 | 依据 |
| --- | --- | --- |
| 交互方式 | 纯 TCP，无附件 | 玩家直接连 |
| 容器内端口 | **10001** | `listen(10001)`，绑定 0.0.0.0 |
| flag 来源 | 平台注入 `GZCTF_FLAG` → 启动时写入 `/app/flag.txt` | GZCTF 动态 flag 机制 |
| 运行依赖 | python:3.12-slim + pycryptodome + pwntools | `1.py` 的 import |
| 建议内存 | **256 MB**（默认 64 MB 会 OOM） | pwntools 导入即占 60–90 MB |
| 建议 CPU | 10（= 1 核） | 单局 400 回合服务端开销约 1 秒 |
| 网络模式 | 开放 | 无需外网，保持默认最稳 |
| 出题类型 | 动态容器 + 动态 flag | 每队独立实例、独立 flag |

`1.py` 原样使用，不改一行；镜像内不含真 flag，flag 只在容器启动时落盘。

注意：一局要打满 400 回合，每回合两次往返，玩家侧需要一条能维持数分钟的长连接；中途断线只能重开。

## 2. 现场已确认的情况

- **平台能拉 Docker Hub 镜像**：`nginx:alpine` 测试容器创建成功。
- **平台使用 WebSocket 代理（PlatformProxy）**：实例入口是 `wss://c404ctf.jellyspot.cc/api/proxy/...`，不是 `ip:port`。玩家不能直接连容器，必须先把 wss 地址映射成本地端口。
- 代理协议：WebSocket 二进制帧直通 TCP，无鉴权，wss 地址本身就是凭证；单条连接上限 30 分钟，同一容器最多 32 条并发。
- **本机网络到不了 Docker Hub**（`registry-1.docker.io` 超时），所以本机 `docker login` / `docker pull` / `docker push` 全都不通；镜像必须换地方构建。
- 题目类型是「动态容器」，而 GZCTF 的动态容器**不支持上传附件**（`IsAttachment()` 只对 StaticAttachment / DynamicAttachment 为真），连接脚本只能写进题目描述或提示。

## 3. 产物

`deploy/`：

- `Dockerfile` — 构建镜像
- `entrypoint.sh` — 把 `GZCTF_FLAG` 写入 `flag.txt` 后启动服务
- `solve_remote.py` — 解题脚本，`python solve_remote.py <host> <port>`
- `wsreflect.py` — 把 wss 地址映射成本地 TCP 端口，给玩家用

`.github/workflows/build-image.yml` — 云端构建并推送镜像（见第 4 节方案 B）。

题目根目录另有 `.dockerignore`，避免 `flag.txt` 进入构建上下文。

本地已验证：模拟 `GZCTF_FLAG` 注入后，服务端 400 回合正常应答；再经过一层 WebSocket 代理转接，解题脚本依然全胜并取回 flag。

## 4. 构建镜像

本机到不了 Docker Hub，因此二选一。

### 方案 A · 本机有代理时

在 Docker Desktop → Settings → Resources → Proxies 里填入你的代理地址，重启 Docker Desktop，然后：

```bash
cd "C:\Users\24456\Desktop\GZCTF\2026日月盾\决赛\剪刀石头布"
docker login
docker build -f deploy/Dockerfile -t <DockerHub用户名>/rps-2026f:latest .
docker push <DockerHub用户名>/rps-2026f:latest
```

### 方案 B · 云端构建（推荐，无需本机 Docker 和代理）

把整个「剪刀石头布」目录推到 GitHub 仓库（公开仓库最省事），工作流文件已经写好，推上去就会自动构建并发布到 ghcr.io。

仓库结构保持这样即可：

```
1.py
deploy/Dockerfile
deploy/entrypoint.sh
.github/workflows/build-image.yml
```

推完之后在仓库的 Actions 页面能看到构建任务，成功后镜像地址是：

```
ghcr.io/<你的GitHub用户名>/<仓库名>:latest
```

注意用户名和仓库名都要小写，工作流里已经自动转成小写。

第一次构建完成后，去这个包的设置页面确认可见性是 **Public**（GitHub 的容器包默认可能是私有，公开仓库不一定自动继承）。位置：个人主页 → Packages → 选中该包 → Package settings → Change visibility → Public。

## 5. 后台配置（比赛 3 → 题目 326）

| 字段 | 值 |
| --- | --- |
| 题目名称 | 剪刀石头布 |
| 分类 | Crypto |
| 类型 | 动态容器 |
| 容器镜像 | 方案 A：`<DockerHub用户名>/rps-2026f:latest`；方案 B：`ghcr.io/<用户名>/<仓库名>:latest` |
| 服务端口 | `10001` |
| CPU 限制（0.1 CPUs） | `10` |
| 内存限制 (MB) | `256` |
| 存储限制 (MB) | `256`（Docker 后端不生效，只对 K8s 有效） |
| 网络模式 | 开放 |
| 流量捕获 | 关闭 |
| Flag 模板 | `C404{R0ck_Sc1ss0rs_P4p3r_[TEAM_HASH]}` |

模板含 `[TEAM_HASH]` 时平台跳过 Leet 熵校验，每队得到唯一 flag。容器内的静态 `flag.txt` 只作本地调试，不要写进模板。

## 6. 玩家怎么连（重要）

平台走 WebSocket 代理，题目描述里必须写清连接方式，否则选手拿到 `wss://` 地址会不知道怎么用。

推荐写法：

> 本平台题目使用 WebSocket 代理，请二选一：
>
> 方式一：安装 WebSocketReflectorX 客户端，在题目页面点击「连接」，平台会把地址映射到本地端口，然后用该端口连接。
>
> 方式二：下载 `wsreflect.py`，执行 `python wsreflect.py <题目页面给出的 wss 地址>`，它会在本地 `127.0.0.1:10001` 起一个转发；再用 nc 或脚本连 `127.0.0.1 10001`。

由于动态容器不能挂附件，脚本内容要么整段贴进描述，要么放到你们自己的文件分享地址。

## 7. 上线验收

1. 题目页点「创建测试容器」，成功后复制完整的 `wss://` 地址
2. 本机跑 `python deploy/wsreflect.py <wss地址>`，看到本地监听提示
3. 另开终端跑 `python deploy/solve_remote.py 127.0.0.1 10001`，应打印该队的 `[TEAM_HASH]` flag
4. 换另一个队伍账号再看一次，两个 flag 必须不同
5. 题目状态置为「启用」，比赛 3 里可见

## 8. 常见坑

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 容器反复重启 / OOMKilled | 内存 64 MB 太小 | 提到 256 MB |
| 能连上但一回合就断 | 提交了 rock/scissors/paper 之外的内容 | 题目本身逻辑 |
| 平台报镜像不存在 | 镜像名不匹配或包不是公开 | 核对 tag、把包设为 Public |
| wss 地址连不上 | 用的测试地址但容器已销毁 | 重新创建测试容器 |
| 打到一半断线 | 代理单连接上限 30 分钟 | 重开一局 |
| 选手不会连 | 描述里没写 WebSocket 连接方式 | 见第 6 节 |
